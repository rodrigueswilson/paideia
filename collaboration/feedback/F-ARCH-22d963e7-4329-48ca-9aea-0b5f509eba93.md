## Finding and rationale
Identity and locators are underspecified exactly where rework costs the most: every learning object, quotation, event and later graph edge points at a segment. Suppose segment identity depends on one extractor's output, such as page and character offsets or chunk numbers. Then upgrading Docling, falling back to another extractor, re-running OCR, or Zotero replacing an attachment will silently orphan approved objects or point them at the wrong text.

The gate "Import same document twice without duplicate identity" can only be tested once the identity keys are defined. The baseline does not say whether identity is the Zotero item, the file bytes or the extracted text.

## Evidence (URLs, observed tests, or explicit unknowns)
- Baseline: the domain model lists "Stable IDs, bibliographic identity, version/hash, source locators, extraction engine and quality" but does not define the keys. The extraction candidates are explicitly expected to change after benchmarking. MVP gate: "import same document twice without duplicate identity".
- VERIFIED: the W3C Web Annotation Data Model (Recommendation, 2017) defines TextQuoteSelector (exact text, with prefix and suffix) and TextPositionSelector (start and end) (https://www.w3.org/TR/annotation-model/). A proven anchoring scheme that does not depend on the extractor already exists to reuse instead of inventing one.

## Proposed change and alternatives
Recommended: layered identity, small enough to decide now.
- Source: a Paideia UUID plus an ExternalReference, such as the Zotero library and item key, or, for Kindle highlights, the Obsidian vault-relative path plus a note hash.
- Document: the SHA-256 of the original bytes. The original is never modified. Paideia stores the hash and the external path or attachment key, and does not necessarily keep a copy.
- Extraction: keyed by (document hash, engine, engine version, settings hash). It produces a normalized text artifact with its own hash.
- Segment anchor: a TextQuoteSelector (exact text plus prefix/suffix, after a documented normalization), plus a TextPositionSelector or page hint that is valid for one Extraction. Objects cite anchors, not chunk numbers.
- Quotation check: the quote must match the cited Extraction text exactly as a substring, after normalization. If it fails, the object cannot be approved. Generated content stores a GenerationRecord (model, prompt version, input anchor IDs) and is rendered only through schema-validated templates that are not HTML.
- Re-extraction resolves the anchors again. An anchor that no longer resolves flags its object for review; the object is not dropped.

Alternative: pin a single extractor per document permanently and store only page + offset. Simpler now, but it locks in the extractor choice and breaks when OCR is re-run.

## Implementation impact and acceptance test
Decide now: the four keys and the anchor format, since they shape every table. Defer: fuzzy re-anchoring heuristics and an OCR confidence UI. Cost of getting it wrong: migrating every approved object and event whenever the extractor changes.
