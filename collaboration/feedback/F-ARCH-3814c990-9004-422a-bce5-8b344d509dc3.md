## Finding and rationale
REQ-10 (confirmed) requires reusing Research MCP, and the reuse policy puts internal code first. Yet the architecture section already names a concrete stack (FastAPI, React, SQLAlchemy/Alembic, SQLite/FTS5, Docling as primary extractor) before Research MCP has been audited. If Research MCP already ingests Zotero, extracts PDFs or keeps an index, Paideia risks a second, diverging ingestion pipeline and index over the same library. That contradicts "No duplicate source-of-truth stores".

Separately, naming Docling as the primary extractor brings a heavy ML dependency set into the first slice before there is evidence that born-digital PDFs need it. (Born-digital PDFs already contain a text layer.)

## Proposed change and alternatives
Recommended:
- Make the read-only Research MCP audit a hard gate for locking in the stack, and for nothing else. Classify each Research MCP capability (Zotero access, extraction, chunking, search, LLM adapter) as reuse as a library, call as a service, keep as reference, or ignore. If Research MCP is Python and already ingests Zotero and PDFs, Paideia's backend should import or call it instead of reimplementing that.
- If the audit finds nothing reusable, keep the proposed stack as the default. It is proportionate: one process, one database file, no message broker.
- Extraction for slice one: a text-layer extractor behind an `Extractor` interface. Docling and OCR come in only after the benchmark shows the text-layer extractor failing on the owner's real mix of documents.
- Before adopting any dependency, record its install size, number of transitive dependencies and license. The registry already has fields for most of this; add "install footprint".

Alternative: adopt Research MCP unchanged as Paideia's ingestion service, and keep Paideia purely as the learning layer. This needs the least code, but ties Paideia's provenance guarantees to code that was not designed for them.

## Implementation impact and acceptance test
Decide now: no Paideia ingestion code before the Research MCP classification exists, and the extractor sits behind an interface with text-layer extraction first. Defer: the final extractor, OCR and the LLM framework. Cost of getting it wrong: two pipelines and two indexes to maintain, or a multi-gigabyte dependency for a capability not yet needed.

Measurement: on 20 representative authorized PDFs, run the text-layer extractor and Docling. Compare wall-clock time per page, peak RAM, install size, and the quotation-check pass rate on 100 hand-picked passages. Adopt Docling only where it changes the pass rate materially; the owner sets that bar after seeing the numbers.
