## Finding and rationale
The proposed sync protocol is a general design in which every device can write: per-device cursors, optimistic concurrency for mutable content, a conflict policy, tombstones and clock-skew handling. The stated mobile need is narrower: study cached content while the PC is off, then upload answers without duplicates. Building general sync before the need is measured is the likeliest source of expensive, low-value complexity.

Separately, the "responsive PWA first" path has an unstated infrastructure prerequisite. An offline PWA needs service workers, and service workers need a secure context. A host serving plain HTTP on a LAN address is not one. The PWA path therefore requires TLS with a certificate the Android devices trust (a private CA, or a private-network product that issues certificates) before any offline test can run. Browser storage is also best-effort: the browser can evict it unless persistence is granted.

## Proposed change and alternatives
Recommended: a read-mostly device, with different data flowing in each direction.
- Host to device: the host publishes immutable, versioned content packs for a selected goal or session. A pack holds objects, the segments and media they need, and a manifest hash. The device swaps packs whole and never merges them.
- Device to host: the device keeps an append-only outbox of events, each with a UUID event_id, occurred_at from the device clock, and the pack/object version. The host ingests them idempotently (unique key on event_id) and acknowledges. In the first mobile milestone this is the only data the device sends.
- No content editing, approval or deletion on the device in that milestone. That removes optimistic concurrency and most tombstone logic. Deleting content means withdrawing the pack at the next refresh.
- Client: keep one React/TypeScript UI. When offline use is tested, ship it to Android inside a Capacitor shell, so the assets are local and offline does not depend on TLS. Or run it as a PWA, but only once private-network HTTPS exists. Decide by the test below, not now.

Alternative: a PWA over private-network HTTPS (for example a VPN mesh that issues certificates) that requests persistent storage. Fewer build tools, more network setup.
Alternative: defer offline entirely; in slice one the phone uses the host online over the LAN.

## Implementation impact and acceptance test
Decide now: the one-way-per-direction rule (in milestone one the device never authors shared mutable state), and that the host database enforces event_id uniqueness. Defer: the packaging framework, the remote-access path, and a conflict policy for mutable content (until a real need for editing on the device appears). Cost of getting it wrong: weeks spent on conflict resolution nobody uses, or a PWA that silently loses its cache.

Test on a real phone and tablet: load a 50-object pack and power off the host. Answer 200 items over 48 hours, force-killing the app twice. Reconnect and replay the upload twice. Pass if the host holds exactly 200 events with the correct pack versions and the cache survives a reboot. Record the pack size and the bytes uploaded.
