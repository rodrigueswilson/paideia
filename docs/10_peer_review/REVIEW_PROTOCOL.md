# Independent review protocol
Freeze v0.1 baseline, provide identical sanitized master specification and selected supporting docs to reviewers, assign roles and withhold other feedback. Ask for critical findings with evidence and concrete alternatives. Record model/version if known, date, scope and baseline hash. Do not confuse model agreement with verification. Reviewers should mark claims not independently checked. Lead validates primary sources, resolves overlap, evaluates tradeoffs against owner goals, then publishes response matrix and v0.2 changes. Owner decides requirement changes. Preserve rejected findings and reasons.

Severity: critical = threatens core purpose/data/security or blocks implementation; major = material architecture/pedagogy risk; moderate = important but bounded; minor = clarity or low-impact issue. Confidence separate from severity. Prioritize 5–10 substantive findings rather than feature brainstorming. Suggested reviewer roles: architecture, learning sciences, open-source reuse, data/sync, SLA, UX/mobile, AI reliability, security/privacy/license, scope/feasibility, adversarial general review. One model may cover several roles but report limitations.
